# Що на вечерю? (dinner_bot)

Telegram-бот для вибору повсякденної їжі з урахуванням продуктів, часу та техніки. 
Мови інтерфейсу: Українська, Русский (визначається автоматично).

## 🚀 Локальний запуск (macOS / Linux)

1. **Перевірте версію Python:**
   Потрібен Python 3.12+.
   ```bash
   python3 --version
   ```

2. **Створіть віртуальне середовище (venv):**
   ```bash
   python3 -m venv venv
   ```

3. **Активуйте venv:**
   ```bash
   source venv/bin/activate
   ```

4. **Встановіть залежності:**
   ```bash
   pip install -r requirements.txt
   ```

5. **Створіть бота:**
   Напишіть [@BotFather](https://t.me/BotFather) у Telegram, створіть нового бота і отримайте токен (`BOT_TOKEN`).

6. **Заповніть конфігурацію:**
   Скопіюйте шаблон:
   ```bash
   cp .env.example .env
   ```
   Відкрийте файл `.env` і вставте ваш `BOT_TOKEN`.

7. **Запустіть бота:**
   ```bash
   python3 -m app.main
   ```
   Бот готовий до роботи! Напишіть йому `/start` у Telegram.

8. **Запуск тестів:**
   ```bash
   pytest
   ```

## ☁️ Розміщення на Render.com

Бот використовує SQLite, тому для збереження даних потрібен **Persistent Disk** (доступно на платному тарифі Starter).
Схема розгортання: Background Worker.

1. **Завантажте проєкт у GitHub** (без файлу `.env` та папки `data/`).
2. Зареєструйтесь на [Render](https://render.com/).
3. Створіть новий сервіс через Blueprint (кнопка "New" -> "Blueprint").
4. Підключіть ваш GitHub репозиторій і оберіть файл `render.yaml`.
5. Перевірте ресурси: буде створено **Background Worker** (тариф Starter, ~$7/міс) та **Persistent Disk** 1GB (~$0.25/міс).
6. В панелі керування Render для створеного Worker-а перейдіть у вкладку **Environment** і додайте змінну:
   - `BOT_TOKEN` = `ваш_токен`
   - `ADMIN_IDS` = `ваш_telegram_id` (через кому, якщо кілька)
7. Збережіть і дочекайтеся завершення Deploy.
8. Перевірте **Logs** — бот має запуститися і вивести "Starting bot...".
9. **Важливо:** Якщо ви запускали бота локально, вимкніть локальний процес (Ctrl+C), щоб уникнути конфлікту polling-процесів.

### Резервні копії бази даних

База зберігається на Render у `/var/data/dinner_bot.sqlite3`.
Для завантаження бази локально, ви можете використовувати Render SSH:
```bash
# Підключіться по SSH до Worker'а
sqlite3 /var/data/dinner_bot.sqlite3 ".backup /tmp/backup.sqlite3"
# Далі завантажити файл /tmp/backup.sqlite3 на локальний ПК
```
*Альтернатива: додати адмін-команду для відправки файлу бази в Telegram.*

## Обмеження 1-ї версії
- Пошук за фото та голосовими повідомленнями відсутній.
- Відсутній поділ на складні кулінарні заміни продуктів (заміни прості або не враховуються).
- Базовий парсер тексту ігнорує складні форми запитів (для покращення потрібен LLM-ключ, див. `llm_adapter.py`).

## Архітектура
- **aiogram 3.x** — для взаємодії з Telegram.
- **aiosqlite** — для асинхронної роботи зі збереженням (налаштування, історія, покупки).
- **Pydantic** — для конфігурації.
- Архітектура базується на поділі бізнес-логіки (`services`), бази даних (`database`) та UI/Telegram (`tg_bot`).
