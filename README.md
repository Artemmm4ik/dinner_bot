# Ужин / Вечеря — Telegram-бот с интернет-поиском и Stars

Готовый исходный проект для Python 3.12, aiogram 3, Render Free Web Service и внешнего PostgreSQL. Интерфейс RU/UK автоматически следует языку Telegram. Меню выбора языка нет.

## Интернет-рецепты: прямой парсинг, без API-ключей

Первая кнопка меню — **«Найти рецепт в интернете»**. Бот использует публичные карты сайтов **Клопотенко, SHUBA и Еда**, ищет адреса по названию блюда/продуктам и загружает страницы найденных рецептов. Из разметки `schema.org/Recipe` извлекаются название, ингредиенты, время и выход, если они есть. Доступны состав в Telegram, ссылка на приготовление у автора, следующие результаты и сохранение.

**Поискового API, регистрации в нём, платы за запрос и дневных/месячных квот нет.** Есть технические ограничения: не чаще одного запроса к источнику раз в 2 секунды (или реже согласно robots.txt), 5 проверяемых страниц на выдачу, ограничение размера ответа, таймауты и кэш в PostgreSQL. Не выполняется обход CAPTCHA, входа, блокировок или запрещённых robots.txt страниц. Не все страницы получится прочитать, не каждый адрес из карты сайта останется действительным.

В комплекте — **78 817 уникальных адресов** (Клопотенко: 4 543; SHUBA: 16 826; Еда: 57 448), собранных с сайтов, **не фиксированный набор из 36 блюд**. Поиск выполняется по словам в адресах с русско-украинскими синонимами продуктов; это не полный поисковик по всему интернету и не строгий поиск по каждому ингредиенту. Лучше запрос «курица картошка» или «борщ», чем длинное предложение. Сначала проверяются страницы предпочтительного языка, но название и состав сохраняют язык автора, без автоматического перевода. Интерфейс всегда на языке Telegram.

**Обновление:** администратор может вызвать `/refresh_sources` — обновятся свежие карты источников (не чаще раза в сутки). Полная пересборка на компьютере: `python -m scripts.sync_sources --all` после установки зависимостей и настройки `.env`, затем новый Deploy. Полная пересборка может занять несколько минут. В фоне на спящем Render задачи не запускаются.

Plus позволяет одним нажатием сохранить план из первых трёх найденных рецептов или составить план из 3/5/7 сохранённых ссылок. Можно получить состав всех блюд плана. Количества остаются как у авторов: граммы, ложки и упаковки автоматически не объединяются, порции не пересчитываются. Ограничения питания интернет-рецептов нужно проверить самостоятельно.

Отдельный **«Подбор с расчётом продуктов»** использует 36 встроенных рецептов с известными ингредиентами: здесь работают строгие фильтры по данным каталога, масштабирование порций, автоматические планы с заменами и суммирование покупок. Эти расчёты не выдаются за проверку всех рецептов из интернета.

## Возможности

Бесплатно:
- интернет-поиск прямым парсингом сайтов, состав рецептов и сохранённые ссылки;
- подбор встроенных рецептов из имеющихся продуктов, приоритет «использовать сначала», ограничения времени и оборудования;
- исключения продуктов, вегетарианский режим и фильтры известных аллергенов;
- порции, пошаговая готовка, оценки, история и избранное;
- покупки с отметками и объединением одинаковых ингредиентов;
- один демо-план из 3 ужинов с двумя заменами, без оплаты и без автоматической подписки.

Plus — **149 Stars каждые 30 дней**, цена задаётся `STARS_PRICE`:
- автоматические планы из каталога на 3/5/7 ужинов;
- «меньше разных продуктов» или «больше разнообразия»;
- замена отдельных блюд и создание нового плана с текущими ограничениями;
- общий список продуктов для плана;
- сохранённые интернет-планы из самостоятельно выбранных ссылок.

Истёкшая подписка запрещает создание платных планов и платные замены. Существующие планы остаются доступны. Демо не повторяется после `/delete_me`. Платный статус проверяется на сервере, а не только скрытием кнопки. Технические ограничения источников распространяются на всех пользователей.

## Быстрый запуск на Render Free

1. Создайте бота через **@BotFather**, сохраните токен. Для тестов заведите отдельного бота.
2. Создайте внешний PostgreSQL, например проект **Neon Free**. Скопируйте строку подключения с `sslmode=require`. Не используйте файл SQLite на Render: файловая система там непостоянная. Проверяйте текущие квоты Neon в его кабинете.
3. Для интернет-парсинга никакие API-ключи не нужны. Индекс адресов уже включён в проект.
4. Загрузите **содержимое папки** этого проекта в свой GitHub-репозиторий. `app`, `render.yaml` и `requirements.txt` должны лежать в его корне. Не загружайте `.env`, токены и базы данных.
5. Render → New → Blueprint → подключите репозиторий. `render.yaml` создаёт **один Free Web Service**, без worker, cron и платного диска. Вручную можно создать Web Service с Build `pip install -r requirements.txt`, Start `python -m app.main`.
6. Заполните Environment из таблицы ниже. После создания сервиса проверьте `WEBHOOK_BASE_URL`: это точный HTTPS-адрес Render, без `/telegram`. Если адрес ещё неизвестен, установите его и повторите Deploy.
7. Дождитесь Live и откройте `https://ВАШ-СЕРВИС.onrender.com/healthz`. Ответ `{"status":"ok"}` означает, что веб-процесс работает; это не полная проверка Telegram/БД.
8. Напишите боту `/start`, выполните сценарии из `TEST_REPORT.md`.
9. Настройте поддержку, администратора, ознакомьтесь с условиями продаж, затем установите `PAYMENTS_ENABLED=true` и выполните отдельную проверку Stars. До этого реальные счета не выдаются.

### Переменные окружения

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен BotFather |
| `DATABASE_URL` | URL внешнего PostgreSQL с SSL |
| `BOT_MODE` | `webhook` на Render |
| `WEBHOOK_BASE_URL` | `https://имя.onrender.com` |
| `WEBHOOK_SECRET` | Случайная строка 32–256 символов; Blueprint генерирует её |
| `PAYMENTS_ENABLED` | `false` сначала; `true` для выдачи счетов |
| `STARS_PRICE` | `149` |
| `SUPPORT_CONTACT` | Реальный контакт `@username`; обязателен при включении оплаты |
| `ADMIN_IDS` | JSON-массив Telegram ID, например `[123456789]` |
| `PORT` | `10000`, Render также может задавать свой порт |

Секрет вручную: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

**Render Free и внешняя PostgreSQL имеют собственные квоты.** Бот не использует платный поисковый сервис. Если источник изменит разметку или доступ, соответствующий адаптер потребуется обновить; при недоступности показывается понятное сообщение.

Render Free засыпает после простоя. Первый запрос может ждать пробуждения; предоплата Telegram требует быстрого ответа и может быть отклонена при задержке. Пользователь может повторить попытку после пробуждения. Искусственные пинги для обхода сна не настроены. Напоминаний по времени нет.

## Telegram Stars: что реализовано

- `createInvoiceLink`, валюта `XTR`, одна цена, `subscription_period=2592000`.
- Проверка владельца счёта, суммы, валюты, срока действия и уже активной подписки при `pre_checkout_query`.
- Один счёт на пользователя в течение часа; при незавершённой предоплате повторная покупка может потребовать нового счёта через час. Это защита от параллельного оформления, а не повторного списания.
- Доступ выдаётся только по `successful_payment`, срок берётся из `subscription_expiration_date`, а не прибавляется повторно при каждом обновлении.
- Уникальный `telegram_payment_charge_id`, транзакционная запись, обработка повторной доставки и возвратов.
- Кнопка отключения автопродления через `editUserStarSubscription`. Дополнительно пользователь может управлять подпиской в Telegram → Мои звёзды.
- `/paysupport` показывает контакт и идентификаторы последних платежей владельцу аккаунта.
- Администратор: `/refund USER_ID TELEGRAM_PAYMENT_CHARGE_ID`, затем отдельное подтверждение. Возврат полный за выбранное списание. Автопродление управляется отдельно — при прекращении подписки его тоже нужно отключить.
- `/terms`, `/privacy`, `/delete_me`. Удаление данных питания сначала пытается отменить продление; платёжные записи и отметка демо остаются.

Нельзя выдавать Plus на основании нажатия кнопки «оплатил». Старые оплаченные подписки продолжают соответствовать цене сохранённого заказа, даже если `STARS_PRICE` изменён для новых покупок. В интерфейсе дата в UTC, это явно подписано.

## Язык

Берётся `from_user.language_code` текущего пользователя: `ru`/`ru-*` → русский; `uk`/`uk-*` → украинский; остальные → украинский. Если Telegram не прислал код, используется последнее известное значение или украинский. Изменение языка приложения подхватывается на следующем сообщении/нажатии. Бот предназначен для личных чатов.

## Запуск на Mac / локально

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

В `.env` укажите тестовый токен, тестовую PostgreSQL и `BOT_MODE=polling`. Затем:

```bash
python -m app.main
```

Если у токена уже настроен webhook, локальный запуск остановится, **не удаляя рабочий webhook**. Для полноценной проверки оплат лучше отдельный тестовый webhook-бот. Существующий production-токен одновременно в двух местах не запускайте.

## Обновление присланного проекта

Перед обновлением сохраните резервную копию внешней PostgreSQL. Схема расширяется автоматически при старте: существующие таблицы пользователей, покупок, избранного и истории не удаляются. Первые 10 ID рецептов сохранены, 20 старых заглушек удалены; их старые карточки могут стать недоступны. Проверьте условия питания в новом интерфейсе после обновления: старый формат свободных исключений не преобразуется автоматически в новые переключатели.

Старые кнопки без соответствующего действия сообщают, что устарели, и открывают новое меню. Черновики диалогов могут потребовать `/start`. Не используйте старый скрипт переноса SQLite: в исходном проекте он мог дублировать строки. Для старой SQLite нужна отдельная контролируемая миграция; данный выпуск рассчитан на уже используемую PostgreSQL или новую пустую базу.

## Проверки и структура

```bash
python -m pytest -q
ruff check app tests
```

- `app/main.py` — HTTP webhook, секрет, обработка до ответа Telegram, healthcheck.
- `app/database/` — PostgreSQL, данные, подписки, платежи, планы.
- `app/tg_bot/internet.py` — поиск, сохранённые ссылки, интернет-планы.
- `app/services/web_recipes.py` — прямой HTML/XML-парсинг, robots.txt, безопасный список источников и кэш.
- `app/tg_bot/payments.py` — Stars, поддержка, отмена.
- `app/tg_bot/handlers/app.py` — бесплатные функции и автоматические планы.
- `app/services/planner.py` — разбор продуктов и подбор из структурированного каталога.
- `app/services/recipe_data.py` — 36 рецептов; расширяется отдельно от интернет-поиска.

Списки покупок включают весь необходимый объём: пользователь сообщил названия имеющихся продуктов, но не точный остаток. Один план добавляется в покупки один раз; после замены блюда нужно очистить список и добавить актуальный план. Рецепты не являются медицинскими рекомендациями и не проходили кухонные испытания.

## Что не проверено без ваших ключей

Реальная покупка и возврат Stars, развёртывание Render и транзакции на вашем PostgreSQL. Прямые страницы Клопотенко, SHUBA и «Еды» проверены сетевыми запросами; это выборочная проверка, а не проверка всех адресов. Автотесты выполняются с подменёнными сетевыми вызовами и БД; это не замена проверке после подключения. Подробный статус — `TEST_REPORT.md`.
